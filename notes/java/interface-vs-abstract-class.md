# 概述

抽象类回答"是什么"（is-a），接口回答"能做什么"（can-do）——这是两者所有语法差异的根。抽象类是单继承、带构造方法和共享代码的模板；接口是多实现、无构造方法、字段全常量的能力契约。Java 8 的 default 方法让接口能带方法体，模糊了边界，但设计语义没变，面向接口编程仍是主流。

# 详细内容

- **一句话本质**：抽象类 = is-a（身份/模板，复用代码）；接口 = can-do（能力/契约，规范行为）。
- **8 点区别**：
  1. **关系**：抽象类 `extends` 单继承（一个子类只能有一个抽象父类）；接口 `implements` 多实现（一个类可多个），接口间可 `extends` 多个接口。
  2. **构造方法**：抽象类**有**（供子类 `super` 调用，自己不能 `new`）；接口**没有**。
  3. **字段**：抽象类可有任意成员变量；接口字段默认全是 `public static final`（只能放常量）。
  4. **方法**：抽象类可有抽象方法 + 普通方法（带方法体）；接口 Java 8 前只能有抽象方法。
  5. **方法修饰符**：抽象类各种都行；接口方法默认 `public abstract`。
  6. **default/static 方法（Java 8）**：接口能有 `default`（带方法体）、`static` 方法——最常被追问的"新"区别。
  7. **private 方法（Java 9）**：接口能有 `private` 方法（供 default 复用），但仍无实例字段。
  8. **设计语义（灵魂）**：抽象类 is-a 模板复用代码；接口 can-do 契约规范行为。
- **default 方法为什么加**：为**向后兼容**——Java 8 给 `Collection` 加 `stream()` 等方法，若接口只能有抽象方法，所有老实现类全得改坏；default 让接口提供默认实现、老实现类不用动。
- **diamond 冲突**：一个类实现两个接口，两接口有同名同参 default 方法 → 编译报错，**必须在该类重写**解决，用 `接口名.super.方法()` 选一个。这也解释了为什么接口字段必须 `final`（多继承下字段可变会成糊涂账）。
- **什么时候用哪个**：多个类有公共代码/模板骨架 → 抽象类（复用代码，但受单继承限制）；定义跨类层次的行为规范/能力契约 → 接口（多实现、解耦）；Java 8 后接口有 default，实际开发更倾向面向接口编程。
- **必背类比**：抽象类像"亲爹"（一个人只有一个亲爹，单继承，继承血脉+家产=字段+代码）；接口像"技能证书"（一个人可考很多证——驾照/英语证/编程证，多实现，每张证一种能力，跟物种无关）。鸟和飞机都实现 `Flyable` 但无共同父类——接口让不相关类共享能力。
- **面试标准答法**：抽象类用 abstract 声明、extends 单继承、有构造方法（供子类 super 调）、可放抽象方法+普通方法+任意字段，表示 is-a 模板，用于代码复用；接口用 interface 声明、implements 多实现、没有构造方法、字段默认 public static final、方法默认 public abstract，表示 can-do 契约，用于解耦和规范行为。Java 8 后接口能有 default/static 方法体、Java 9 能有 private 方法，但语义不变——共享代码和身份用抽象类，定义跨类层次的能力契约用接口。
