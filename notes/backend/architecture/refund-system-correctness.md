# 概述

- 退款系统的第一原则不是“尽量自动化”，而是资金正确性：不能多退、错退、超过可退金额，也不能把支付结果丢在系统外。
- 风控评分只能解决“谁风险高”的问题，不能替代退款资格校验、状态机、幂等、查单和对账。
- 面试中要先说业务不变量，再说系统结构；否则容易过早落到“打分 + 阈值”这类局部方案。

# 详细内容

## 业务不变量

- 同一笔售后退款请求只能被执行一次；重复请求只能返回已有退款单状态。
- 退款金额不能超过订单剩余可退金额，已全额退款订单不能再次全额退款。
- 只有满足订单状态、支付状态、售后期限、商品状态等资格条件时，才允许进入自动退款流程。
- 支付接口超时不能直接当作失败；系统应进入 `UNKNOWN` 或 `PROCESSING`，再通过查单确认终态。
- 本地退款记录、支付渠道记录和财务账单最终必须可核对、可解释、可修复。

## 判断逻辑：硬规则优先

- 第一层是退款资格校验：订单是否已支付、是否在售后期内、是否已经退款、剩余可退金额是否足够、订单状态是否允许退款。
- 第二层是高风险硬规则：短期退款次数过多、退款率异常、历史恶意退款、异常物流、高金额退款等，命中后转人工。
- 第三层才是风险评分：对未被硬规则截断的灰度用户综合账号行为、物流轨迹、历史客诉和退款频率打分。
- 复杂风控可以延期，但基础硬规则不能省；复杂评分被砍时，可以用“高频 / 高金额 / 黑名单 / 异常物流转人工”兜底。

## 状态机

- 状态机关注“当前状态、触发事件、合法迁移”，不是把业务流程写成几个阶段名。
- 退款主链路可以是：`CREATED -> CHECKING -> AUTO_APPROVED / MANUAL_REVIEW -> REFUND_PROCESSING -> REFUND_SUCCESS / REFUND_FAILED / REFUND_UNKNOWN`。
- 人工审核链路可以是：`MANUAL_REVIEW -> APPROVED / REJECTED`，只有审核通过才进入 `REFUND_PROCESSING`。
- 严格禁止的迁移包括：成功后重新处理中、人工未通过直接退款、未调用支付渠道直接标记成功、已全额退款再次全额退款。
- 终态要收口；已关闭、已拒绝、已成功的退款单不能被普通重试重新拉回处理中。

## 幂等与重复点击

- 幂等键不能简单使用 `user_id + order_id`，因为一个订单可能存在部分退款、分商品退款或多笔售后单。
- 更合适的业务幂等标识是 `refund_request_id`、`refund_order_id`、`merchant_refund_no` 或售后单 ID。
- 本地创建退款单时用数据库唯一约束兜底，调用支付渠道时也携带同一个商户退款单号。
- 重复请求不应该直接丢弃，而应该返回第一次请求对应的退款状态：处理中返回 `PROCESSING`，成功返回 `REFUND_SUCCESS`。
- 幂等解决“重复执行”，状态机解决“非法流转”，两者需要配合而不是互相替代。

## 超时、查单与最终一致性

- 支付接口超时只能说明调用方没拿到结果，不能证明支付渠道没有执行。
- 超时后本地状态应保持 `UNKNOWN` 或 `PROCESSING`，并启动主动查单、定时补偿或人工介入。
- 查单依据应使用 `refund_id` / `merchant_refund_no`，避免只按订单号模糊匹配。
- 明确成功后更新为 `REFUND_SUCCESS`；明确失败且渠道确认未执行后，才允许更新为 `REFUND_FAILED` 或重新发起。
- 如果本地事务和异步消息并存，需要关注消息是否发送成功、消费者是否重复消费、补偿任务是否可重入。

## 链路排查

- 当前端显示“退款已受理”但后端没有记录时，先确认提示来源：前端本地状态、网关返回，还是退款服务真实返回。
- 排查顺序应沿请求链路找断点：前端请求、API 网关、退款服务入口、退款单创建、事务提交、异步流程、支付调用。
- 如果支付退款 API 没有被调用，重点在支付前链路，不要一开始就查支付侧后置流程。
- 工程手段包括 `trace_id`、`request_id`、`order_id`、网关日志、服务日志、数据库事务日志、MQ 日志和支付调用日志。

## 对账

- 对账第一步不是逐笔查订单，而是统一统计口径。
- 需要先确认时间范围、统计时间字段、退款成功定义、币种、手续费、部分退款、退款渠道等口径是否一致。
- 口径一致后，再用 `merchant_refund_no` 或 `refund_id` 做逐笔匹配，排除双方都存在且金额一致的正常单。
- 差异单常见类型包括：本地成功但渠道无记录、渠道成功但本地无记录、金额不一致、重复退款、状态不一致。
- 差异处理要区分自动修复和人工处理；资金系统不能只发现差异，还要能解释差异、修复差异。

## 面试答题骨架

- 原则：先说资金系统不变量，例如超时不等于失败、退款必须幂等、状态必须可追踪。
- 方案：再说硬规则、状态机、唯一幂等键、支付调用、查单和对账。
- 兜底：最后说人工审核、补偿任务、差异单和复杂风控延期方案。
