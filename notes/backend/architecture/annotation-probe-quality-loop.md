# 概述

- 标注业务的根本难题：**产出本身就是标准答案（GT），没有更上游的答案可对照**——全量复检双倍成本、抽查是递归问题、纯信任没有测量
- 探针机制一次解决：用少量确定正确的历史样本，换取对整个任务质量的持续测量
- 类比**神秘顾客**：伪装成普通顾客的检查员混在日常客流里，店员才对每个顾客用同样标准——**探针的价值建立在"不可识别"上**

# 详细内容

## 注入：floor 取整保不变量

- 注入数 = floor(目标总量 × 探针比例)，创建任务时悄悄混入，界面零标识
- 选 floor 而非 round/ceil 的理由：**保证"探针占比不超过运营配置上限"这个不变量**
  - round 超配：25 × 10% = 2.5 → round 得 3（实际 12%），floor 得 2
  - ceil 最激进：0.1 → 1，任何小比例在小任务里都至少注入 1 个
- 取整方向的理由比 floor 本身更值得讲——它是个"保不变量"的设计决策

## 比对：两层判定

- 值对象 `ProbeMatchResult`：validity_match / tag_match / match_percent / is_correct
- **先硬性维度一票否决、再按重叠度算软性分数**：有效性或标签任一不一致直接 0%；都一致则按关键帧重叠度算（重叠 ≥80% 计为匹配帧）
- 与 ML 评测 precision/recall 的思路同构

## 分流与飞轮

- 探针全对 + auto_review 开启 → 自动免人工审核（管理员从全量复核收缩到只看有问题的）
- 有错 → 进人工审核（看探针匹配卡 + 统计）
- 审核通过的任务自动沉淀为新探针源——"标注 → 审核 → 参考样本 → 再注入"的**数据飞轮**，正确答案库随业务增厚

## 四大价值

- **质量测量**：客观度量每个标注员/任务/类型的正确率，喂绩效与运营看板
- **威慑效应**：不可识别 → 必须对所有样本同等认真——激励相容的机制设计案例
- **降本提效**：探针全对自动免审
- **数据资产复利**：正确答案库越用越厚

## 边界防御（体现深度）

- **不可识别性**：接口返回、界面渲染与普通样本零差异，用验收标准锁死
- **复选治理**：探针源重注入会把池内样本复活（active 重置）→ 候选查询加 `NOT IN (困难样本库)` 硬排除
- **版本绑定**：标注标准升级后，探针只能从**当前标准版本**的样本中选——旧答案不能判新卷子
- **比例可配**：探针比例/最低匹配度/自动审核开关按任务类型独立配置

## 通用启发

- 无 GT 场景的质量保障范式：**用少量确定正确的存量，换全量的持续测量**（同思路：代码覆盖率、A/B 审计样本）
- 派生状态不落库：样本状态由 decision + 票数 + 上限纯函数派生（O(1)、无双写不一致）
