# 概述

- **21 合并两个有序链表**是基本原语：23（合并 K 个）、148 排序链表的归并步都是它的复用
- **23 合并 K 个**的核心只剩一个问题：「怎么高效选当前最小」——堆 or 分治，都是 O(N log k)（N=总节点数，k=链表条数）

# 详细内容

## 21 合并两个：取小者接尾

- 不变量：**cur 指向已合并段的尾部**；每轮比较两个当前头，**取较小者接到 cur 后面**，只前进被取走的那个指针，另一个原地不动
- 口径纠正：「把大的接在小的后面」是结果不是操作，白板上用不变量口径说不会绕晕
- 尾部整段接入一行：`cur.next = list1 or list2`（谁剩接谁，可能都为 None）
- dummy + 返回 `dummy.next`；O(m+n) 时间、O(1) 空间；递归版存在但 O(m+n) 栈空间，面试说迭代版

## 23 堆解法

- 堆存三元组 `(val, i, node)`：**序号 i 是挡箭牌**——值相等时 heapq 会去比较第三元素 ListNode，没有 `<` 定义直接 TypeError
- 初始每条链表头入堆（跳过空链）；每轮弹最小接到 cur 后，被弹节点的 next 非空则回推
- **堆不变量：每条链表在堆里最多贡献一个节点**（弹一个才推它的 next）→ 堆大小恒 ≤ k，每次 push/pop O(log k)，N 个节点各进出一次 → **O(N log k)**

## 23 分治解法

- 迭代版：每轮**全员**相邻配对合并，k 条 → k/2 条 → k/4 条…共 ⌈log₂k⌉ 轮，每轮每个节点恰好被合并一次 O(N) → **O(N log k)**
- 递归版：`mergeK(l, r) = merge(mergeK(l, mid), mergeK(mid+1, r))`
- 两法对比：堆 O(k) 辅助空间、适合流式/动态到达；分治常数更小（无堆调整、访问顺序缓存友好），递归栈 O(log k)

## 复杂度陷阱：串行归并不是 O(mn)

- 「每次取两个合并、放回池子」若池子每轮只减一（串行并入），总账 = 2m + 3m + … + km = O(mk²) = **O(N·k)**
- 具体：k=4、每条长 m → 2m + 3m + 4m = 9m，随 k 平方增长
- 「两两合并」要配得上 O(N log k)，必须是**每轮全员配对**（即分治），不是逐条并入

## 148 排序链表：归并是链表的天选

- **为什么链表亲归并、数组亲快排**：快排 partition 要随机访问 + 双向交换，单向链表没下标没前驱直接残废；归并 merge 只要顺序访问（21 原语），链表合并是纯指针重接 O(1) 空间。反过来数组上归并要 O(n) 辅助数组、快排缓存友好——**数据结构决定排序算法的亲和力**
- 组装零新件：[B 条件找中点](linked-list-fast-slow.md)（生死线：A 条件 n=2 死循环）→ `slow.next = None` 断开 → 递归两半 → 21 合并；出口 `if not head or not head.next`
- 递归栈 O(log n) 一般被接受；严格 O(1) 空间 → **自底向上迭代归并**：step = 1, 2, 4, 8… 每轮按步长切段、两两归并缝合，直到 step ≥ n

## 2 两数相加：同步推进造新链（合并骨架的模拟变体）

- **竖式逐位吐节点**：`t = a + b + carry`（走完的链 a/b 按 0），新节点值 `t % 10`、`carry = t // 10`——从头到尾**不存在累加的整数 sum**，别把链表还原成大数再求和
- 逆序存储是本题的善意：头节点 = 个位，head→tail 扫描序 = 竖式低位→高位计算序；正序存储（445 两数相加 II）就得先反转链表或用栈，麻烦一档
- `while l1 or l2 or carry:` 把末尾进位折进循环（`[5]+[5]→[0,1]` 零特判）；dummy 口径②：造新链统一首节点创建
