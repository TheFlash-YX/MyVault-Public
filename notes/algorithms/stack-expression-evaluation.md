# 概述

- 中缀表达式（人写的）优先级裸露在外；227 无括号 `+-*/` 用「一个栈 + prev_op 哨兵」一遍扫描求值

# 详细内容

## 核心分野：`+ -` 能拖，`* /` 不能拖

- `+ -` 只是项与项的分隔符 → 数字**带符号压栈**（`+num` / `-num`），拖到最后 `sum(stack)`
- `* /` 绑架相邻操作数 → 必须在数字读完的那一刻与栈顶**立刻融合**，否则 `3+2*2` 会被算成 `(3+2)*2`
- 结算时机：读到**运算符**或**最后一个字符**时，按 prev_op 处理刚读完的数字

## 四种 prev_op 的处理

| prev_op | 动作 | 含义 |
|---|---|---|
| `+` | `stack.append(num)` | 正项，先欠着 |
| `-` | `stack.append(-num)` | 负项（减号变负号）|
| `*` | `stack.append(stack.pop() * num)` | 立刻融合 |
| `/` | `stack.append(int(stack.pop() / num))` | 立刻融合 + 向零取整 |

## prev_op='+' 哨兵（单位元家族）

- 任何表达式 ≡ 前面补 `"0+"`；0 是加法单位元 → 第一个数当正项压栈，**免第一个数的特判**
- 同族：198 `dp0=dp1=0`（空和）、152 `dp0=dp1=1`（空积）、max → `-inf`（求和→0、求积→1、取 max→-inf）
- 迁移口诀：写循环前先问「第一轮会不会踩到未初始化状态？能否用哨兵把它变成普通一轮？」

## 数字读取与结算时机

- 多位数字逐字符累积：`num = num*10 + int(ch)`
- 收尾：最后一个字符也要触发结算（`i == len(s)-1`），否则末尾数字丢失
- 不能每读到一个数字字符就压栈；例如 `14` 必须先累积为一个整数，否则会被误当成 `1` 和 `4` 两项。
- 两个判断应是独立的 `if`：先累积数字，再检查是否遇到运算符或末尾；最后一个字符为数字时，需要在同一轮完成这两步。
- 遇到当前运算符时，用旧的 `preop` 处理完整的 `num`，之后才执行 `preop = ch`、`num = 0`。例如 `3+2*2`：遇到 `+` 结算 3，遇到 `*` 按旧 `+` 压入 2，末尾按旧 `*` 算得 4，最后求和得 7。
- 最后一个字符可能是空格；使用末尾下标触发结算时，不要让提前 `continue` 跳过该轮收尾。末轮把数字或空格赋给 `preop` 无妨，因为之后不再使用它。
- 另一种收尾方式是遍历 `s + '+'`，靠补充的运算符触发最后一次结算；这会创建长度 `O(n)` 的新字符串。
- `s.replace(' ', '')` 返回新字符串，不会原地修改 `s`；可以接收返回值，也可以在原串遍历中忽略空格。

## 无栈版：累计结果与当前项

- `result` 保存已经结束的项之和，`last` 保存仍可能接上乘除的当前带符号项；初始均为 0。
- 每读完一个完整数字，仍按旧的 `preop` 结算：旧符号为 `+/-` 时先做 `result += last`，再令 `last = num/-num`；旧符号为 `*` 时令 `last *= num`，为 `/` 时令 `last` 与 `num` 相除并向零取整。
- 遍历结束返回 `result + last`；扫描原字符串并用末尾下标收尾，才能严格保持 `O(1)` 额外空间。
- 栈版时间 `O(n)`、空间 `O(n)`；无栈版时间 `O(n)`、空间 `O(1)`。本次无栈版只讲解思路，尚未手写。

## Python 专属坑：`//` 向下取整，题目要向零取整

- `-3 // 2 = -2`（floor，往 -∞ 方向）；题目 truncate 语义要 `-1`；正数无差，**负数且除不尽才分叉**
- 负数来源：`-num` 压栈技巧让栈里出现负的中间结果——`14-3/2` 手推：栈 `[14, -3]`，`-3/2` 应得 -1（答案 13），`//` 得 -2（错成 12）
- 正解 `int(a / b)`：先算浮点真实值，`int()` 一律砍向 0
- 纯整数版防大数精度：`a // b if a >= 0 else -((-a) // b)`
- C/Java/Go 的 `/` 天生向零取整，此题在那边无此坑

## 表达式三写法与计算器家族

- 同一算式 `3+2*2`：中缀（人写，需优先级+括号）/ 前缀（波兰）`+ 3 * 2 2` / 后缀（逆波兰 RPN）`3 2 2 * +`
- 前后缀靠**运算符位置**编码计算顺序，无需优先级规则
- 后缀求值 = 数字压栈、运算符弹二算一压回（LC 150 逆波兰表达式求值，比 227 还简单）
- 227 的栈本质是**简化版调度场算法**（shunting yard）：标准流程「中缀→后缀→栈求值」两遍扫描，因 `* /` 可当场融合、`+ -` 可带符号压栈而并成一遍；栈中留下的项即后缀表达式求值到一半的现场
- 难度阶梯：150 后缀求值 < 227 无括号 `+-*/` < 224 有括号 `+-` < 772 有括号 `+-*/`；每加一种「顺序被打乱」的机制（优先级→括号→一元负号）就需要更强结构消化

## 参考实现（227）

```python
class Solution:
    def calculate(self, s: str) -> int:
        stack, num, prev_op = [], 0, '+'
        for i, ch in enumerate(s):
            if ch.isdigit():
                num = num * 10 + int(ch)
            if (not ch.isdigit() and ch != ' ') or i == len(s) - 1:
                if prev_op == '+':   stack.append(num)
                elif prev_op == '-': stack.append(-num)
                elif prev_op == '*': stack.append(stack.pop() * num)
                else:                stack.append(int(stack.pop() / num))
                prev_op, num = ch, 0
        return sum(stack)
```
