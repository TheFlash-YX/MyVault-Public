# 概述

- 把「依赖关系」建模成**有向图**：点 = 任务，边 = 先决依赖，方向从**先决指向后续**（`[a, b]` 表示先学 b 再学 a，边是 `b → a`）
- 判断能否全部完成 ⟺ 图中**无环**：环 = 循环依赖 / 死锁，环里每个点都被环内另一个点依赖，永远找不到「第一个」
- 两种判环/排序写法：**Kahn（BFS，摘入度 0 的点）** 与 **三色 DFS（遇灰即环）**，二者等价

# 详细内容

## 建图

- 邻接表 `graph[b].append(a)`：记录每门课的后继课
- 入度数组 `indeg[a] += 1`：每门课还剩几个先决课没学

## Kahn 算法（拓扑排序）

- 入度为 0 的点（无先决依赖）入队；每摘一个点，它所有后继的入度 -1，新出现的入度 0 点再入队
- **摘下总数 == n** ⟹ 无环、能完成；**还有剩余但摘不动** ⟹ 剩下的全在环里

## 三色 DFS（等价写法）

- 白=0 未访问 / **灰=1 正在递归栈上** / 黑=2 已完成
- 递归时当前点涂灰；遇到**灰邻居 = 撞到回边 = 有环**；离开时涂黑
- ⚠️ 易错（实际踩过）：比较的是 `colors[邻居]`，**不是邻居编号本身**——曾把 `colors[y]` 误写成 `y`，最简用例 `[[1,0]]`（应返回 True）直接误报 False

## 复杂度

- O(V + E)：建图 O(E)，每个点入队/出队一次 O(V)

## 钥匙反例

- 最简环 `[[1,0],[0,1]]`：学 1 要先学 0、学 0 要先学 1，**没有任何一门课能先学**——这就是「环 = 循环论证」的直觉来源
