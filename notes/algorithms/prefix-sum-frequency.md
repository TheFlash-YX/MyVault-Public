- 数组可能有负数或 0，不能用普通滑动窗口根据当前和与 k 的大小单向调整边界。

# 详细内容

## 为什么前缀和之差保证连续

- 定义 `pre[i]` 为前 i 个元素的和，`pre[0]=0`。
- 闭区间 `[l,r]` 的和为 `pre[r+1]-pre[l]`；相同的前半段抵消后，只留下从 l 到 r 的连续元素。
- 当前前缀和 s 与此前前缀和 p 需满足 `s-p=k`，故查找的是 `p=s-k`，不是 `k-s`。
- 当前扫描到 r 时，只使用此前记录过的前缀和，因此对应的起点一定不晚于 r。

## 频次表与顺序

- 字典保存“此前前缀和 → 出现次数”，因为同一个值出现多次时，每次对应一个不同的起点。
- 初始记录 `0:1`，表示尚未读取元素时的空前缀，可统计从下标 0 开始的子数组。
- 每读一个 num，按“更新当前和 → 查询 `s-k` 的历史次数并加到答案 → 记录当前 s 一次”的顺序处理。
- `nums=[1,-1,0]、k=0`：处理最后一个 0 时，当前和 0，此前的和 0 已出现两次，分别产生 `[1,-1,0]` 与 `[0]`。
- 应使用次数而非 `set` 或“是否出现”，否则会漏算不同起点形成的区间。
- 若用 `defaultdict(int)`，可直接 `ans += freq[s-k]`，但读取不存在的键会新增一个零值键；先做成员判断可避免这一点，两种写法都正确。
- 平均时间 O(n)，最坏需要存 n+1 个不同前缀和，空间 O(n)。

## 本次代码修正

- 首稿先统计所有前缀和再查询，会把未来前缀和当成起点；应在一次遍历中只记录历史。
- 首稿使用 `presum[i]<k` 与 while：负数使大小比较不能决定有无目标；查到多次时一次性累加频次即可。
- 普通字典不能对尚不存在的键直接 `dic[pre]+=1`，会报 KeyError；可用 `get(pre,0)+1` 或 `defaultdict(int)`。
- 曾在更新当前前缀和之前查询补数，导致 `[1]、k=1` 漏算；改为先 `pre+=num` 再查。
- `ans` 需在循环前初始化为 0；最终版本已修正这些问题。
