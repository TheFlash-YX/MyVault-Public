# 详细内容

## 415：字符串相加

- 两个指针从各自字符串末尾开始；某一端已经用完时，本位数字按 0 处理。
- 每轮 `total=dig1+dig2+carry`，本位数字为 total%10，下一轮进位为 total//10。
- 循环在任一指针仍有效或者 carry 非零时继续，避免遗漏 99+1 的最后一个进位。
- 本题每轮最大总和为 9+9+1=19，carry 只可能为 0 或 1，因此用户的 `or carry==1` 正确；`or carry` 是等价简写。
- 数字字符先 append 到列表，结束后 reverse 再 join；避免反复向字符串头部插入导致重复复制。
- 两个输入长度为 n、m 时，时间和辅助空间均为 O(max(n,m))，列表、反转和拼接的成本都已包含。

## 43：字符串相乘

- m 位与 n 位数相乘，结果最多 m+n 位；用户最初认为 m+n-1 位，反例是 9×9=81，因此结果数组开 m+n 个位置。
- 字符下标从左往右编号，计算时两层循环都从右往左；下标编号方向与遍历方向不是一回事。
- num1[i] 与 num2[j] 相乘，低位位置为 i+j+1，进位位置为 i+j；不同乘积可能贡献到同一个位置，必须保留此前的累积值。

```python
total = int(num1[i]) * int(num2[j]) + result[i + j + 1]
result[i + j + 1] = total % 10
result[i + j] += total // 10
```

- 低位用赋值，因为 total 已包含原低位；进位位置用累加。外层遍历哪个输入均可，保持从低位向高位处理。
- 用户首稿在末尾使用 `ans=ans*10+digit` 重建完整乘积，收到“使用任意精度整数重构结果”的限制提示；这不是 Python 语法错误，而是违背本题不使用大整数的要求。
- 最后直接将每个数位转成字符，用 `''.join(str(digit) for digit in result)` 拼接；不再重构完整数值。
- `ans.lstrip('0') or '0'` 去掉前导零，并在乘积全零时返回字符串 0。
- 中间版本使用循环字符串相加，后改成 join，避免依赖特定实现的拼接优化；join 使结果构造为 O(m+n)。
- 两层乘法时间 O(mn)，额外空间 O(m+n)。任一输入为 0 时提前返回只是可选优化，用户最终版本未采用。

## 165：比较版本号

- `version.split('.')` 得到字符串列表，例如 1.02.3 变成 `["1","02","3"]`；比较当前段前再转 int，忽略前导零。
- 从最左段依次比较；缺失段当作 0，所以 1.0 与 1.0.0 相等。
- 遇到第一段不同就立即返回 1 或 -1；只有所有段都相等才能返回 0。
- 用户最初提出遍历时反复更新 flag，最后返回。反例 2.0 与 1.9：第一段已确定前者更大，后面的 0<9 不能覆盖此前结论。
- 完整字符串的字典序不代表版本大小：字符串 10 小于字符串 2，而整数 10 大于 2。
- 两个列表的访问位置同步增加，可统一为一个下标，遍历到 max(n,m)；无需实际给较短列表补零。
- 按题目单段整数范围约束，两个原始字符串长度为 L1、L2 时，时间 O(L1+L2)，split 的额外空间 O(L1+L2)。

## 8：字符串转换整数 atoi

- 严格按顺序处理：跳过开头空格 → 读取至多一个符号 → 连续读取数字 → 遇到非数字停止 → 加上符号并限制范围。
- 空格只能在最开始跳过，不能删除中间空格；符号之后也不能再次跳过空格或符号。
- 用户曾认为 12 34 应得到 1234、符号后仍可跳过空格，现已纠正。

| 输入 | 结果 | 停止原因 |
|---|---:|---|
| `"12 34"` | 12 | 数字中间遇到空格 |
| `"+-12"` | 0 | 读过一个符号后又遇到符号 |
| `"  - 12"` | 0 | 符号后遇到空格，尚未读到数字 |
| `"   +0012-34"` | 12 | 连续数字结束于减号 |
| `"   + 0012"` | 0 | 正号之后不能继续跳过空格 |

- 不必收集数字列表再 join，直接用 `num=num*10+int(c)` 累积；没有读取到数字时 num 保持 0。
- 用户首稿跳过空格后直接访问 s[idx]，空串和全空格会导致 idx==len(s)，必须先返回 0 或做边界守卫。
- 只有一个符号时，符号读取后下标到末尾，数字循环不执行，最终返回 0，结果正确。
- 先得到带符号的 result，再截断：`max(-2**31, min(2**31-1, result))`。正负边界不对称，不能把负下界写成 -(2**31-1)。
- Python 整数可增长，因此当前“先完整累积，最后截断”的写法可以处理题目范围并已报告通过；但对不受长度限制的输入，大整数乘法、加法和存储不能始终按 O(1) 计算。
- 指针扫描本身至多 O(n)。若要保证通常所说的 O(n) 时间、O(1) 辅助空间，应在累积时判定超界并提前返回，使 num 始终有界；这项优化只讨论过，用户尚未实现。
