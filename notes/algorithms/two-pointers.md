# 概述

- 同向双指针的五种模型：间距定位（链表倒数第 k）、就位区（原地压缩数组）、逆向填充（原地合并）、判环（相对速度）、走两程（相交链表等路程）
- 核心方法论：先说清**不变量**（`[0, slow)` 是什么、`[slow, fast)` 是什么），再写代码

# 详细内容

## 间距模型（剑指22 链表倒数第 k 个节点）

- 快指针先走 k 步制造 `gap = k`，再与慢指针同步后移；快指针到 null 时慢指针正好停在倒数第 k 个节点，一次遍历 O(n)/O(1)
- **删除场景的区别**（19 删倒数第 N 个）：要删除必须停在**前驱**节点——让快指针多走一步（k+1 步）或加 dummy 头节点

## 判环模型（141 环形链表）

- slow 每轮 1 步、fast 每轮 2 步；无环方向 fast 触 None 自然出循环；有环方向用**相对速度**论证必相遇
- 一旦 slow 进环（fast 必已先在环中），看沿环间距 g（fast 领先 slow 的步数）：fast 每轮追 2、slow 逃 1，**g 每轮恰好减 1**
- 整数逐轮减 1 必**精确经过 0**——不可能从 1 直接跳到 −1；这一句同时回答「为什么必相遇」和「为什么不会越过」，关键是步差恰为 1
- 上界白话：进环后至多 L−1 轮相遇，slow 在环内走不满一整圈（「slow 一圈 fast 两圈」是这个上界的口语版，不是机制）
- 追问备着：fast 改走 3 步 → g 每轮减 2，可能从 1 直接跳 −1，偶数长度环里隔点永远错过
- 模板陷阱：`slow = fast = head` 起点**先动后判**——先判后动，第一步就「相遇」在自己身上；`while fast and fast.next` 天然覆盖空表与单节点

## 就位区模型（283 移动零）

- 不变量：`[0, slow)` 是已就位的非零元素（保持原相对顺序），`[slow, fast)` 全 0
- `slow` 指向下一个非零元素应放置的位置；已就位区域保持原顺序，不要求数值有序。遇到非零元素才交换并推进 `slow`，`fast` 每轮都推进。
- `fast` 遇非零 → `swap(nums[slow], nums[fast])` 且 `slow += 1`；`slow == fast` 时为自交换，无副作用
- 每次交换的本质：非零元素进就位区、一个 0 换进零区，因此不会丢元素
- 反例：与数组**末尾**交换（快排 partition 式）不稳定——`[0,1,0,3,12]` 中 12 会跳到最前面，破坏非零元素相对顺序
- 同模板复用：27 移除元素、26/80 删除有序数组中的重复项

```python
def moveZeroes(nums):
    slow = 0
    for fast in range(len(nums)):
        if nums[fast] != 0:
            nums[slow], nums[fast] = nums[fast], nums[slow]
            slow += 1
```

## 逆向合并（88 合并两个有序数组）

- 正向合并的坑：写指针会追上 nums1 的读指针，`[1,2,3] + [2,5,6]` 中 2 写到下标 2 处覆盖了未读的 3（除非开 O(m+n) 临时数组）
- 正确做法：三指针 `i = m-1`、`j = n-1`、`write = m+n-1`，每轮取**较大者**放 `write` 位
- 循环条件只写 `while j >= 0`，统一两个边界：`j` 耗尽 → nums1 前缀本来就位直接收工；`i` 耗尽 → else 分支把 nums2 剩余依次入位
- 两段循环也正确：先在两个读指针都有效时比较，再补入 nums2 剩余元素；nums1 剩余前缀已经在正确位置，无需搬动。
- 有效元素数量 `m` 决定 nums1 的末尾读指针为 `m-1`，不是 `m-n-1`；预留容量只影响写指针的初始位置。
- 88 与 283 都要求原地修改并返回 `None`，不要返回数组；88 时间 `O(m+n)`，283 时间 `O(n)`，两者额外空间均为 `O(1)`。
- 通用技巧：目标数组空位在**尾部**、源数据在前部时，从大端倒着填（31 下一个排列同为此类逆向思维）

```python
def merge(nums1, m, nums2, n):
    i, j, write = m - 1, n - 1, m + n - 1
    while j >= 0:
        if i >= 0 and nums1[i] > nums2[j]:
            nums1[write] = nums1[i]
            i -= 1
        else:
            nums1[write] = nums2[j]
            j -= 1
        write -= 1
```

## 走两程模型（160 相交链表）

- 判定「同一节点对象」（不是值相等），所以循环条件写 `while pa is not pb`（`!=` 只是恰好退化成身份比较，意图不对）
- **等路程设计**：设 A 独有 a、B 独有 b、共享 c；pa 走 A→换 B，pb 走 B→换 A，两人路程都是 a+b+c → 同速必同时踏进交点。不是「碰巧相等」，是换路机制把不等长两链拉成等长路线
- **不相交时相遇在 None**：c=0 时两人各走 a+b 步同时到 None，`pa is pb` 照样成立——循环退出和返回值**一行通吃**两种结局，这是本题最漂亮处
- 没有换路机制：两指针死在各自链尾、不等长时死的时刻都不同，「相遇」无从谈起
- 「长度对齐」解法（长链先走差值再同步）与走两程是同一数学事实的两种实现：事后补（走完换路）vs 事先消（先走差值）

```python
def getIntersectionNode(headA, headB):
    pa, pb = headA, headB
    while pa is not pb:
        pa = pa.next if pa else headB
        pb = pb.next if pb else headA
    return pa
```
