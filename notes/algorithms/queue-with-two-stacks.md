# 概述

- 入队栈接收新元素，出队栈按队首顺序提供元素；逐个弹出再压入另一个栈，可以逆转顺序。
- 只在需要 `pop()` 或 `peek()` 且出队栈为空时，搬运入队栈的全部元素。

# 详细内容

## 操作规则

- `push(x)`：压入 `instack`。
- `pop()`：必要时搬运，然后弹出 `outstack` 栈顶。
- `peek()`：必要时搬运，然后读取 `outstack[-1]`，不移除元素。
- `empty()`：只有两个栈都为空，队列才为空，即 `not self.instack and not self.outstack`。
- `[1, 2, 3]` 从入队栈逐个倒入出队栈后变为 `[3, 2, 1]`，栈顶 1 正好是队首；只搬一个元素会错误地先取出 3。
- 出队栈非空时不能继续往里面搬：其中的元素比入队栈中的元素更早入队，需要先出队。

## Python 实现易错点

- `__init__` 中的局部变量不能作为跨方法状态；使用 `self.instack`、`self.outstack`，其他方法也通过 `self` 访问。
- `self.empty` 是方法对象，`self.empty()` 才会调用方法并得到布尔值；`if not self.empty` 不会进入分支。
- LeetCode 保证 `pop()`、`peek()` 调用时非空，因此可以省略队列判空。若希望支持空队列，必须让检查控制最终读取；只包住搬运逻辑、末尾仍然无条件弹栈，并不能防止报错。

## 单次最坏与均摊

- `push()`、`empty()` 为 `O(1)`；一次 `pop()` 或 `peek()` 若触发 n 个元素搬运，最坏为 `O(n)`。
- 每个元素最多压入入队栈一次、从入队栈弹出一次、压入出队栈一次、从出队栈弹出一次，总计固定次数操作。
- n 次入队加 n 次出队的总成本为 `O(n)`，均摊到每次调用为 `O(1)`；任意长度为 q 的操作序列，从空队列开始的总成本为 `O(q)`。
- 例如先入队 5 个元素再出队 5 次，只有第一次出队需要搬运 5 个元素，其余四次直接弹栈。
- 多次 `peek()` 不会反复搬运同一批元素。均摊是整个序列的成本保证，不依赖随机概率，也不意味着每次调用都一样快。
- 空间复杂度为 `O(n)`，n 为队列中的元素数。
