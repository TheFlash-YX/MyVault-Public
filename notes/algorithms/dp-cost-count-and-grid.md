# 详细内容

## 322：零钱兑换

- dp[x] 表示凑出金额 x 的最少硬币数；dp[0]=0，其余为 inf，表示尚不可达。无穷大加一仍不可达。
- 外层金额从 1 到 amount，内层遍历硬币；x>=coin 时 dp[x]=min(dp[x],dp[x-coin]+1)。所有面额为正，所依赖的更小金额已经计算。
- 最终仅当 dp[amount] 仍为 inf 时返回 -1；不能因某种面额不合适提前返回。
- 实际误区：写 dp[x]+1 而不是 dp[x-coin]+1；依据剩余金额是否大于最小面额判断可达性。剩余 0 表示恰好完成，[2] 凑 3 则即使大于最小面额也不可达。
- [1,3,4] 凑 6，末枚选 1、3、4 对应 3、2、3 枚，取 2；优先大面额的贪心会失败。
- A 为金额、k 为面额数：时间 O(Ak)，空间 O(A)。不同面额依赖不同距离，不能照搬只保存前两个状态的优化。

## 70：爬楼梯

- dp[i] 是到第 i 阶的方法数，最后一步来自 i-1 或 i-2；两类最后步长不同、互不重叠，所以 dp[i]=dp[i-1]+dp[i-2]。
- 实际误区是 max(dp[i-1],dp[i-2])+1：题目不是求最长长度，补一步也不是额外增加一种方法。n=4 正确为 5，错误式得到 4。
- dp[1]=1、dp[2]=2；先处理 n<=2，避免 n=1 时访问 dp[2] 越界。
- 双变量更新为 a,b=b,a+b。分两句 a=b 再 b=a+b 会读到已修改的 a，例如 1、2 会误算出 4。
- 时间 O(n)，空间由 O(n) 降至 O(1)。

## 64：最小路径和

- dp[i][j] 表示左上角到 (i,j) 的最小路径和，含起点和终点；只能向右或向下。
- dp[0][0]=grid[0][0]；第一行、第一列分别求前缀和。内部为 min(dp[i-1][j],dp[i][j-1])+grid[i][j]。
- 从上往下、从左往右遍历，返回 dp[m-1][n-1]；表格就是 m×n，不必添加空前缀边框。
- 一维 dp 先存第一行前缀和，每行先 dp[0]+=grid[i][0]，再对 j>=1 更新 dp[j]=min(dp[j],dp[j-1])+grid[i][j]。
- 旧 dp[j] 是上方，新 dp[j-1] 是左侧；不依赖左上方，所以不需要双序列题的 prev/temp。
- 实际错误：grid[0][i] 写反行列；dp[0]+=dp[0]+grid[i][0] 重复累加旧值。`[[1],[2]]` 会错误得到 4，正确为 3。
- 时间 O(mn)，额外空间由 O(mn) 降到 O(n)，用户的一维版不修改原网格。

## 221：最大正方形

- dp[i][j] 是以当前格子为右下角的全 1 正方形的最大边长，不是面积。输入为字符矩阵，比较的是字符串 "0"、"1"。
- 当前为 0 则状态清零；第一行、第一列为 1 时边长为 1；内部为 1 时取上、左、左上三个边长的最小值再加一。左上为 0、其余三个格子为 1 的 2×2 矩阵不能形成边长 2，说明左上不可省略。
- 答案是全表最大边长的平方，不能只看最后一个格子。
- 真实笔误是 dp[i][j]==0，只比较不赋值；二维表初始为零、每格仅计算一次，掩盖了错误。用户改为 = 后报告通过。
- 一维版更新前的 dp[j] 仍为上一行状态，所以遇到 0 必须清零；先用 temp 保存旧值，下一列仍需要它作为左上方。
- 第一行转换为整数并记录最大值；每行先 prev=dp[0]，再更新首列。每列保存 temp、更新当前值、prev=temp；每行结束以 max(dp) 更新全局最大边长。
- 每行多扫描一次求 max，仍是 O(mn) 时间，不会变成更高数量级。逐格维护 ans 可省重复扫描，但要包含首列，且不能据此保证 Python 实测更快。
- 时间 O(mn)，空间由 O(mn) 降至 O(n)。2026-10-11 用户报告修正后的二维版和一维版均通过；逐格维护 ans 只讨论，未报告另一次实现通过。

## 62：不同路径

- dp[i][j] 为到达该格子的路径数量；来自上方和左侧的路径最后一步不同，互不重复，因此相加。
- 第一行和第一列均为 1，起点的 1 表示不移动的一种方案；单行、单列、单格答案都为 1。二维表整体初始化为 1 可行，内部随后覆盖。
- 一维 dp=[1]*n，按行扫描，对 j>=1 执行 dp[j]+=dp[j-1]；dp[0] 始终保持 1。旧 dp[j] 是上方，新 dp[j-1] 是左侧。
- 不能照搬双变量滚动写成 `dp[j-1],dp[j]=dp[j],dp[j]+dp[j-1]`，这会破坏已计算的状态并污染后续行。反例 m=4、n=3：错误写法返回 9，正确为 10；m=3、n=3 时返回 5，正确为 6。
- 纠正教学记录：助手曾误称上述写法仍正确，撤回时又把反例结果误算为 11；10 月 12 日沉淀时实际运行错误代码，确认应为 9。保留实测反例与标准更新，不沿用旧结论。
- 时间 O(mn)，空间由 O(mn) 降至 O(n)。2026-10-12 用户报告二维版和仅更新当前格子的一维版均通过。

## 139：单词拆分的前缀可达性

- dp[i] 表示前 i 个字符能否完整拆分；dp[0]=True，其他初始 False。空前缀可以用零个单词组成，不要求字典含空串；否则 j=0 时第一个单词无法建立可达状态。
- 枚举 i 从 1 到 n，再枚举 j 从 0 到 i-1；若 dp[j] 且 s[j:i] 在字典集合中，则 dp[i]=True 并 break。只需存在一种拆分，不要求所有切点都成立。
- 用户首稿把 dp[j] 写成 s[:j] in word_set，错误要求前缀本身是单个单词。例如 applepenapple 的前缀 applepen 由两词组成，虽不在字典却可拆分。
- 返回 dp[n]；词可重复使用，无需删除集合元素。状态依赖多个不同长度的前缀，不能直接压缩成两个变量。
- Python 每次切片创建和首次字符串哈希均与长度有关，直接枚举所有切点的时间上界为 O(n³)，不能仅按两层循环判为 O(n²)。这里按集合平均查找模型分析。
- 讨论优化：设最长单词长度为 L，仅枚举 j 从 max(0,i-L) 到 i-1，可得 O(nL²) 的上界（不计字典预处理；若 L>n 可用 min(L,n)）。DP 空间 O(n)，另需字典集合及临时切片；字典构建成本还与词数、总字符数有关。
