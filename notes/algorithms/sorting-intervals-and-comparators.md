# 详细内容

## 56：合并区间

- `intervals.sort(key=lambda x: x[0])` 按左端点升序；首稿 lambda 冒号前缺少参数 x。
- 答案保持有序且互不重叠。当前区间 [c,d] 只需与末段 [a,b] 比较：排序保证 c>=a，而更早答案段的右端点严格小于 a。
- `c<=b` 时重叠，端点相等也算；右端点改为 max(b,d)。用户最初把条件写成 b<=c，方向相反。
- 不重叠时追加当前区间；首稿缺少 else，输入 `[[1,3],[5,7]]` 会漏掉第二段。
- `[[1,4],[2,3]]` 合并仍是 `[[1,4]]`，不能把右端点直接赋成当前段的 3。
- 用户答案列表保存原区间引用，因此更新 ans[-1][1] 会同步修改输入中的子列表；sort 也会修改输入顺序。
- 时间 O(n log n)，扫描 O(n)；答案最多 O(n)，Python 排序辅助空间最坏 O(n)。

## 179：比较真实拼接结果

- 转成字符串后比较 a+b 与 b+a：前者更大就让 a 在前，相等时顺序无所谓；两种拼接等长，可直接按字符串大小比较。
- 不能按整数大小降序，也不能用较短串末尾字符补齐。12 与 1213 的补齐比较会偏向 12，但 121312 大于 121213，应让 1213 在前。
- 12 与 121 并不等价：12121 大于 12112，所以 12 在前；12 与 1212 才拼接相等。
- 排序后首项为 0，说明全部为零，返回字符串 0，避免得到 00；无需转成完整整数。
- 用户实现把 nums 的整数原地改成字符串，可选用新列表保存转换结果以避免改变输入元素类型。
- n 个元素、每个数字最多 d 位，比较成本 O(d)，总时间 O(nd log n)，额外空间 O(nd)。

## cmp_to_key：比较规则与排序的分工

- 普通 key 接收一个元素并提取排序依据；cmp_to_key 将接收两个元素的比较函数转换成排序可使用的 key。
- 比较函数返回负数表示 a 在 b 前、正数表示 a 在 b 后、0 表示优先级相同；不要求恰好是 -1、0、1，也不能只用布尔值表达三种关系。
- 最大数中 a+b>b+a 时返回 -1，意思是把 a 放前，不是“数值大就返回正数”。
- 用法为 `words.sort(key=cmp_to_key(self.compare))`；传函数，不是 self.compare() 的调用结果。
- 用户类内的 compare(a,b) 少了 self，绑定实例后隐式传入 self，再加 a、b 共三个实参，导致 takes 2 positional arguments but 3 were given；修复为 compare(self,a,b)。
- key 对每个元素生成一次包装对象；排序再按需要多次调用比较函数。一个元素可能参与多次比较，顺序由排序算法决定，不是固定比较相邻元素，也不需要枚举所有元素对。
- compare 只回答谁在前，不负责移动元素；可临时打印 a、b 观察调用，但不要依赖某次运行的比较顺序。
- sort 原地修改列表并返回 None；sorted 返回新列表。比较规则须保持一致、避免循环关系；能直接提取 key 时优先普通 key。
