# 今日学习

- 以 DeepTutor 源码为基点梳理 Agent Runtime：Runtime 管理任务生命周期，Turn 表示一次用户请求的执行实例，Session 则承载整段会话和多个 Turn
- 串起 Turn 主链路：Payload 校验与补全 → Session/Sticky Preferences → 模型和工具授权 → 孤儿 Turn 修复 → 创建 `running` Turn → 构建 `UnifiedContext` → Orchestrator 路由 → Capability 执行
- 明确 DeepTutor 顶层 Orchestrator 采用显式规则路由：`active_capability` 指定能力，缺省进入 `chat`；LLM 的语义决策发生在 Capability 内部的 Agent Loop
- 区分 `StreamEvent` 与 `StreamBus`：前者是带类型、正文、元数据和序号的数据协议，后者是 Turn 级异步发布订阅通道；Runtime 负责补充 Turn/Session 标识并持久化事件
- 理解 KB 的在线处理策略：Turn 绑定知识库后按规则挂载 `rag`/`kb_files`，传统 KB 先自动预检索，Agent Loop 中仍可根据语义追加检索
- 梳理 RAG Provider 抽象：KB 在创建时固定绑定 Provider，`RAGService` 根据配置路由到统一 `RAGPipeline`，底层可使用 LlamaIndex、PageIndex、GraphRAG、LightRAG 或远程 IMA
- 复习 Python 异步基础：进程是资源容器、线程是操作系统执行单元、协程是 Event Loop 调度的可暂停任务，`yield` 是生成器产出数据的语法
- 明确 `await` 只暂停当前协程而不自动制造并发；`create_task()` 用于登记独立任务，`gather()` 用于并发等待多个协程，`to_thread()` 用于隔离同步阻塞代码
- 用 DeepTutor 验证异步生成器模型：`await queue.get()` 负责等待事件，`yield event` 负责向 Runtime/WebSocket 逐条交付事件
