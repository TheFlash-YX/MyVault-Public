# 今日学习

- 143 重写版验收 5/5：用的不是我讲的 B 模式而是自洽替代——**A 条件找中点 + `reverse(mid)` 连中点反转**（reverse 第一步 `mid.next=None` 顺便断链，中点成两条链共同尾巴），合并循环 `while head2.next` 在共同尾巴前停手；教训沉淀为「两种模式各自自洽、别混用」
- 234 回文三连问：Q2（B + reverse(slow.next)）答对；Q1 漏了「逐对比较」这个产出答案的步骤（找中点/断链/反转只是准备）；Q3 结论对但理由串了模式——B 模式下奇数中点**不参与比对**（`while p2` 只走后半段长度轮），「公共结尾」是 A 模式的说法
- 234 手写一次过（LC 通过 + 6 case 抽查）：B 条件 + `reverse(mid.next)` + `mid.next=None` + `while p1` 逐对比较，模式用得干净
- 160 相交链表三连问方向全对，补两层精确：① 等路程不是巧合是**设计**——pa 走 a+c+b、pb 走 b+c+a，换路机制把不等长两链拉成等长路线；② 不相交时**相遇在 None**（各走 a+b 步同时到 None，`pa is pb` 照样成立，循环退出与返回值一行通吃）
- 160 手写通过；细节：`while pa is not pb` 用身份比较（`!=` 只是恰好退化，意图不对）；「长度对齐」与「走两程」是同一事实的事先消/事后补两种实现
- 19 删倒数第 N 个三连问全对（fast 先 n+1 步 → slow 落前驱；dummy 兜掉头）；手写通过 + 追问「为什么从 dummy 开始」吃透：**dummy 把「找前驱」变成「在 len+1 扩展链里找倒数第 n+1 个」，n≤len 保证存在，零特判**；反例：无 dummy 版 n==len 时 `None.next` 炸（实测）
